# 心率算法与采样实现

当前算法由 [`pulse_detect.c`](../software/stm32/user/api/pulse_detect.c) 实现；采样集成见 [`adc.c`](../software/stm32/user/api/adc.c)，队列与滤波见 [`pulse_buffer.c`](../software/stm32/user/api/pulse_buffer.c)。硬件接线、操作和构建步骤见 [README](../README.md)，实测验证范围见[验证记录](VALIDATION.md)。

## 数据流与时间基准

```text
TIM3 update TRGO（1kHz）
  → ADC1_CH13（PC3，每次触发一次转换）
  → DMA1 Channel 1 循环数组（20 × uint16_t）
  → 半传输/全传输 ISR：处理对应 10 点块
  → 去一个最大值、一个最小值，剩余 8 点平均
  → 32 槽队列（有效容量 31），保存 value + time_ms
  → 主循环 get_BPM() 排空队列
  → PulseDetector_Process() + PulseDetector_Expire()
  → BPM / IBI → 报警与界面
```

TIM3 时钟按实际 APB1 时钟及定时器倍频规则计算，预分频到 1MHz、周期 1000 个计数。DMA 完成中断以 `Millis()` 记录块完成时间，不取主循环处理时间。采样节拍由硬件维持，时间戳包含毫秒量化及 ISR 响应延迟；不会用固定递增时间补造遗漏块，也不会让故障恢复后的时间戳超前于系统时钟。

DMA 的半传输与全传输同时积压，表示 ISR 已错过缓冲边界，不能保证旧半区尚未被覆盖。此时与 DMA 传输错误一样，置队列故障标志、丢弃不可信历史。这里没有补造丢失样本。

队列写入发生于 DMA ISR。主循环仅在取队列元素时保存 PRIMASK、短暂禁止中断并恢复原状态；算法和 LCD 均在临界区外运行。队列索引、槽内容和故障标志为 `volatile`。

SysTick 维护私有 `volatile uint32_t` 毫秒计数，主循环通过 `Millis()` 只读访问，不再清零 ISR 正在增加的计数器。对时间差使用无符号减法，覆盖 32 位计时回绕。采样 ISR 的优先级低于 SysTick，初始化和前台调度使用同一毫秒基准。

## 参数与状态

| 参数 | 当前值 | 用途 |
| --- | --- | --- |
| 原始采样频率 | 1000Hz | TIM3 触发 ADC |
| 算法采样间隔 | 正常为 10ms | 每块 10 个原始点；IBI 使用传入时间戳 |
| `PULSE_WINDOW_SIZE` | 250 | 约 2.5s 的算法样本窗口 |
| 阈值更新步长 | 25 个算法样本 | 预热后约每 250ms 重新计算窗口极值 |
| 最小窗口幅度 | 20 ADC LSB | 小于该幅度判为弱信号 |
| 高 / 低阈值 | 幅度的 80% / 50% | 触发候选沿 / 复位比较状态 |
| 有效候选间隔 | 300～2000ms，含边界 | 对应 200～30 BPM |
| 发布前确认 | 至少 2 个连续有效间隔 | 首沿只对齐；抑制单次异常沿发布读数 |
| 平滑长度 | 最近最多 4 个有效间隔 | 降低采样量化抖动 |
| `PULSE_TIMEOUT_MS` | 2500ms | 有效输出过期时间 |
| `PULSE_MAX_SAMPLE_GAP_MS` | 100ms | 实际样本缺口或采样停止处理 |
| 队列容量 | 31 块 | 32 槽环形队列保留一槽区分空/满 |

`PulseDetector` 持有窗口、阈值、迟滞状态、候选沿时间、有效输出时间和间隔历史。算法不依赖 STM32 寄存器或全局时钟，可以直接编译到主机执行回归。

## 窗口、迟滞和间隔计算

1. 累计 250 个样本预热，首次窗口就绪时根据当前值对齐比较状态，避免人为生成上升沿。
2. 计算窗口最小值 `min`、最大值 `max`、幅度 `A = max - min`。若 `A < 20`，清读数与候选沿状态。
3. 设置 `low = min + A / 2`、`high = min + 4 × A / 5`；预热后每 25 个样本刷新一次。
4. 信号降至 low 以下后，才允许下一次越过 high 触发候选沿。已复现的 400/300 幅度次峰低于 high，因此不会重复触发。
5. 首个候选沿保存时间。后续沿间隔为当前时间戳与上次候选沿的无符号差值。
6. 小于 300ms 或大于 2000ms 的间隔清连续确认历史，但不刷新有效输出时间。
7. 至少两个连续有效间隔后，用最近最多四个间隔的总和换算并四舍五入输出：

```text
IBI = round(sum(intervals) / count)
BPM = round(60000 × count / sum(intervals))
```

全局 `IBI` 表示平滑后的间隔，`BPM` 为当前有效读数；0 表示无可用读数。平均多个间隔会延缓突变响应，首次发布也需要预热和三个候选沿。

## 失效与恢复

| 触发条件 | 行为 |
| --- | --- |
| 窗口幅度不足 | 清除 BPM、IBI、连续间隔和候选沿，保留窗口更新 |
| 距有效输出更新超过 2500ms | 清除 BPM、IBI 和连续间隔；无效候选沿不能延长该期限 |
| 主循环发现采样已停止超过 100ms | 清除输出；后续样本到达时若实际时间缺口超过 100ms，则完整重新预热 |
| 队列溢出或 DMA 数据不可信 | 丢弃积压历史，完整重置检测器并预热 |
| 距候选沿超过 2500ms | 清候选沿及间隔历史，恢复后先重新对齐 |

`get_BPM()` 每次主循环调用：先处理队列里的原始采集时间，再以当前 `Millis()` 检查停止/过期。LCD 暂停前台时，DMA 仍持续入队；只要未溢出，恢复后不会把处理挤在一起的时间当成采样间隔。

## 回归验证

```bash
python -X utf8 verify/run_native_tests.py
```

该命令直接编译固件共用 C 文件，验证失败通过非零退出码报告。用例见 [`verify/test_pulse.c`](../verify/test_pulse.c)：

- 全部 171 个整数心率点：每点模拟 60s 的 1kHz 合成输入，经过相同 10 点滤波；检查后 30s 持续有有效输出、平均误差小于 1 BPM，且有足够多次有效更新，避免“保持旧值”蒙混过关。
- 60 → 240 BPM：超过范围的候选间隔不能一直保留旧心率；随后切换回有效信号并检查恢复。
- 每秒一周期的高斯双峰（幅度 400/300、相位 0.2/0.55、宽度参数 0.045）：无噪声及轻微噪声时均检查 60 BPM。
- 平直信号、停止采样、恢复到 72/120 BPM。
- 实际 11ms、不规则时间戳、32 位毫秒回绕和超过 100ms 的样本缺口。
- 队列空/满、顺序、索引回绕、时间回绕、溢出后恢复，以及每 150ms 才处理一次的前台暂停。

本次结果为 535,808 条断言全部通过，171 点的最差稳态平均误差为 0.424 BPM。完整环境与编译结果见[验证记录](VALIDATION.md)。

`bpm_fix_verify.py` 是历史 Python 方案对比，未同步改写为当前算法，也不作为修复后的回归依据。

## 当前限制

80% 高阈值是针对较低次峰的幅度判别，不是通用的脉搏形态识别。等高/接近主峰的双峰、强运动伪影、基线突变和信号饱和仍需真实波形验证。边界心率附近也受采样量化影响。

主机回归验证纯 C 检测器、滤波与队列语义；ARM 编译验证集成可编译链接。TIM3/ADC/DMA 的实际节拍、中断延迟、显示负载下的采样、电气质量和真实佩戴精度仍待实物测量。
